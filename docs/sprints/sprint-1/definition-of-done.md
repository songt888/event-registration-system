# Sprint 1 — Product Definition of Done

This is the single product checklist owned by #17; other feature contracts refer to it.

- [ ] Required behavior and backend rules match the merged feature contracts; UI → API → persistent DB journey works.
- [ ] Contract revision is committed before real failing tests, then passing implementation/refactor commits; merge commits preserve history.
- [ ] Planned applicable tests execute and pass, with no required test skipped, weakened or silently removed; failures/skips and incomplete work disclosed.
- [ ] Other student writes a specific review/check and valid approval on the current head; PR is merged to sprint-1-staging. AI assistance does not substitute for teammate review.
- [ ] Integration build and full applicable suite pass on the recorded staging state. QA #40 records TEST-15 and separate TEST-37 five times each and the NFR-06/08/09 checks.
- [ ] README, environment example, contracts and traceability agree; teammate verifies setup from a fresh clone in at most 10 documented commands.
- [ ] Evidence records real commands, exact tested commit, output/counts and automated/manual distinction in docs/evidence/ac-test-results.md; TDD samples retain raw red/green output as required by team workflow.
- [ ] Reviewed release PR staging → main is merged; build, full required tests and planned acceptance checks run on that exact main commit before v0.1.0-sprint1 is created. Remote tag resolves to the verified commit.
- [ ] Screenshots/final results come from the tag; evidence/PDF PRs target staging only and main remains frozen through submission. Final PDF includes Parts A–F, real page numbers, contribution history and honest AI-use/limitations declaration.

These unchecked items are completion gates, not a claim that any has passed. Documentation-only contract preparation uses document checks and no fabricated red/green run.
